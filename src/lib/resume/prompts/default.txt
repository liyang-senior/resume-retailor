## 5. TECHNICAL SKILLS CLASSIFICATION ENGINE

The technical skills section must be specific, comprehensive, logically organized, and relevant to the JD.

### 5.1 Allowed category keys

- Languages
- Frontend engineering

- Messaging

- Engineering practices

Include a category only when relevant.

Never duplicate a category or use alternate labels for the same technical layer.

### 5.2 Category classification rules

**Languages**

Include programming languages only.

Examples: TypeScript, JavaScript, Python, Java, C#, Go, Ruby, SQL.

**Frontend engineering**

Include frontend frameworks, UI libraries, styling technologies, browser tools, frontend rendering/routing techniques, and UI quality techniques.

Examples: React.js, Next.js, Angular, Vue.js, Tailwind CSS, shadcn/ui, HTML, CSS, Responsive Design, Web Accessibility, server-side rendering, client-side routing, client-side rendering, App Router, Server Components.

**Backend engineering**

Include backend frameworks, server runtimes, API technologies, and service development tools. Do not put ORMs/databases here.

Examples: Node.js, Express.js, Nest.js, Ruby on Rails, FastAPI, Spring Boot, REST APIs, OpenAPI, webhooks, API integrations.

**Databases**

Include databases, data stores, ORMs, query technologies, and caching platforms.

Examples: Convex, PostgreSQL, MySQL, MongoDB, Redis, Entity Framework.

**DevOps**

Include CI/CD, containers, infrastructure automation, source control, and deployment tools.

Examples: Git, Bitbucket, GitHub, GitLab, Docker, Kubernetes, Terraform, Jenkins, GitHub Actions, CI/CD.

**Cloud engineering**

Include explicitly relevant cloud platforms and services.

Examples: AWS, Microsoft Azure, Google Cloud, Amazon EC2, Amazon S3, AWS Lambda.

**Security**

Include identity technologies, authentication systems, authorization models, and application security mechanisms.

Examples: Authentication, Authorization, OAuth, JWT, role-based access, multi-tenant access.

**Testing**

Include testing frameworks, automated testing tools, and testing disciplines relevant to the position.

Examples: Jest, Vitest, Pytest, JUnit, Cypress, Playwright, unit tests, integration tests, end-to-end tests.

**Engineering practices**

Include process and collaboration practices only — not tools, frameworks, or frontend techniques.

Examples: code review, technical documentation, software architecture, technical design, Agile, Scrum, mentorship.

### 5.2.1 Classification anti-patterns (never do these)

Wrong → Correct:

- Entity Framework under Backend engineering → Databases
- Responsive Design / Web Accessibility under Engineering practices → Frontend engineering
- Bitbucket / Git / GitHub / GitLab under Engineering practices → DevOps
- server-side rendering / client-side routing / SSR / CSR under Engineering practices or Backend → Frontend engineering
- Tailwind CSS / shadcn/ui / HTML / CSS under Engineering practices → Frontend engineering
- REST APIs / OpenAPI / webhooks under Engineering practices → Backend engineering
- Jest / Cypress / Playwright under Engineering practices → Testing
- Authentication / Authorization under Engineering practices → Security
- TypeScript / JavaScript under Frontend or Backend → Languages

Never dump concrete tools or frontend UI techniques into Engineering practices.

### 6.2 Bullet structure (every details item)

**ACTION + TECHNOLOGY + TECHNICAL IMPLEMENTATION + FUNCTIONAL PURPOSE OR RESULT**

Required in each bullet: past-tense engineering action; named technology/technique; concrete what was built/maintained; clear purpose/result.
